# TERRA — 로봇 기반 원격 청크 계산 설계

> 상태: **설계 확정 / 구현 미착수** · 기록일: 2026-11-14
> 문서 전용 변경. 실제 서버·클라이언트·저장 스키마·테스트 코드는 변경하지 않는다.
> 향후 오픈필드·청크 기반 월드 전환을 전제로 하는 설계이며, 기존 스카이랜드 프로토타입의 구현 현황과 구분한다.

## 1. 목표

TERRA의 행성 월드는 청크 기반으로 확장한다. 플레이어가 멀어지면 일반 청크의 생산·채집 시뮬레이션은 정지한다. **플레이어가 제작·배치한 로봇**은 자신에게 할당된 청크를 플레이어가 멀리 있어도 운영하게 한다. 단, 원격 로봇 청크에서는 지형 메시, 개별 물리 객체, 실시간 애니메이션을 로딩하지 않고 **서버의 자원·공정·전력·물류 계산만** 진행한다.

로봇은 단순 그래픽 장식이나 기존 포탈이 아니라 **원격 산업 가동 권한을 주는 게임 내 제작 장치**다. 플레이어가 재접근하면 계산 결과가 실제 월드 표현에 반영된다.

## 2. 청크 상태

| 상태 | 활성 조건 | 3D 렌더링 | 생산·전력·자원 계산 | 물리·개별 아이템 이동 |
| --- | --- | --- | --- | --- |
| 플레이어 근처(활성) | 플레이어가 로딩 범위 안 | 클라이언트에서 주변 지형과 시설 표시 | 서버에서 진행 | 근거리에서 필요한 범위만 |
| 원격 로봇 운영 | 플레이어는 멀지만 유효한 로봇이 관리 | **안 함** | **서버에서 계산만** | **안 함** |
| 휴면 | 플레이어와 유효 로봇 모두 없음 | 안 함 | 정지 | 정지 |
| 오프라인 | 유효한 활성 플레이 세션 없음 | 안 함 | **전체 정지** | 정지 |

- 플레이어 주변의 렌더링과 서버 산업 계산은 별도 개념이다. 원격 생산을 위해 서버에 Three.js 또는 3D 메시를 생성하지 않는다.
- 로봇을 설치했다는 사실만으로 무조건 가동하는 것은 아니다. 로봇의 배치·작동 상태, 향후 정의될 전력/배터리 조건과 허용 청크 범위를 검사한다.
- 플레이어가 접속 중 우주정거장으로 이동해도, 해당 플레이어의 행성에 유효한 로봇이 있으면 원격 계산을 이어갈 수 있다.
- 동일 청크에 여러 로봇 또는 플레이어가 중첩되어도 **생산 타이머를 중복 실행하지 않는다**.

## 3. 계산 모델

- **서버 권한:** 청크/설비별 원본 상태와 계산 시점을 서버가 관리한다. 클라이언트는 표시만 하고 생산량을 확정하지 못한다.
- **통합 게임 시간:** 기존 합의인 현실 1분 = 인게임 12분의 게임시간을 사용한다. 유효한 접속이 끊어지면 시간 흐름과 원격 공장 계산이 함께 멈춘다. 오프라인 생산 소급은 하지 않는다.
- **이벤트/누적량 정산:** 원격 청크에선 드릴 채굴량, 생성기의 남은 매장량 및 회복량, 기계 입력/출력 재고, 전력 공급/소비, 컨베이어 처리 가능량, 저장고 남은 용량, 로봇 가동 조건을 계산한다.
- **개별 물체 대신 집계:** 원격에서는 컨베이어 위 물건의 프레임별 좌표가 아니라 구간별 재고·전송량·잔여 처리시간을 유지한다. 시각화가 필요한 활성 청크로 전환될 때만 렌더 상태를 재구성한다.
- **물리 없는 채굴:** 원격 자동 드릴이 자연 광석 블록을 채굴하는 설계가 채택되면, 해당 블록 제거 상태를 영구 기록한다. 생성기를 채굴하면 생성기 자원량을 감소시키며 둘을 혼동하지 않는다.
- **경계 연결:** 서로 다른 청크에 설치된 컨베이어, 저장고, 전력선의 네트워크 연결을 추적하고 동일 생산망에서 일관되게 정산한다.
- **제약 준수:** 전력 부족, 원료 고갈, 출력 막힘, 저장고 포화, 로봇 비활성 등 조건을 먼저 판정해 과생산·음수 재고를 방지한다.
- 정산 주기 **실시간 5초**는 성능 실험용 초기 제안일 뿐 확정 수치가 아니다. 정산 간격이 달라도 총 생산 결과가 일관되어야 한다.

## 4. 로봇과 청크 활성화

1. 플레이어는 미래 공업 티어에서 로봇을 제작한다.
2. 로봇을 행성의 지정 위치에 배치하고 관리 청크를 할당한다.
3. 로봇이 유효한 동안, 플레이어가 이동해도 해당 청크의 산업 계산은 중단되지 않는다.
4. 로봇이 철거되거나 동력/배터리 조건을 잃으면, 플레이어가 근처에 없는 경우 계산을 정지한다.
5. 로봇의 청크 관리 반경, 최대 설치 수, 배터리 용량, 소비량, 제작 레시피와 해금 티어는 **미확정**이다. 서버 성능 검증 후 밸런싱한다.
6. 원격 로봇 청크를 실시간 물리·적 AI·전체 월드 시뮬레이션의 일반적인 강제 로딩 장치로 해석하지 않는다. **산업 계산 전용**이다.

## 5. 저장·전환·정합성 규칙

- 저장할 개념 데이터: 청크 식별자, 로봇 배치·소유·운영 상태, 마지막 정산 게임시간, 기계/자원 재고와 공정 진행률, 네트워크 연결 상태, 자연 광석 채굴 변경분.
- 원격 ↔ 플레이어 근처 전환 시 동일 서버 상태를 재사용하고, **한 번의 생산량을 두 번 정산하지 않는다**.
- 청크가 언로드되거나 프로세스가 재시작돼도 직전 확정된 재고와 진행 상태를 복원한다. 오프라인 시간은 추가 생산으로 환산하지 않는다.
- 원격 계산에서 생성된 아이템은 저장고·기계 출력·물류 재고에 반영한다. **플레이어 인벤토리에 자동 지급하지 않는다**. 직접 채집 보상과 기계 산출물을 구별하는 기존 규칙 유지.
- 월드/플레이어 간 상태 격리, 중복 요청에 대한 멱등 처리, 원자적 저장을 구현·테스트한다.

## 6. 미래 구현 순서(실행하지 않음)

1. 오픈필드 청크 식별·저장 및 서버 권한의 통합 게임시간 안정화.
2. 실제 로봇 없이 활성/휴면 청크 간 산업 계산 전환을 테스트 가능한 형태로 분리.
3. 로봇 배치·할당·운영 조건 및 청크별 권한 검사 구현.
4. 자동 드릴·생성기·전력·컨베이어의 **집계형 원격 계산**을 구현.
5. 활성 ↔ 원격 ↔ 휴면 전환과 저장/복원에 대한 정합성 테스트.
6. 실제 모바일/브라우저에서 원격 공장 복귀 시 화면 동기화 및 프레임 성능 QA.

## 7. 필수 검증 시나리오(미실행)

- 로봇 없는 공장에서 멀어지면 생산 정지; 로봇이 있으면 접속 중 생산 지속.
- 로봇 철거/동력 상실 시 즉시 정산 종료; 동력 복구 시 중복 정산 없음.
- 동일 청크 여러 로봇·여러 클라이언트 접속 시 생산량 중복 없음.
- 플레이어가 우주정거장에 있어도 로봇 청크는 계산; 로그아웃하면 정지.
- 1개 생산망이 복수 청크를 가로지를 때 전력·물류·재고 보존.
- 컨베이어가 막히거나 저장고가 가득 차면 원격 생산이 멈춤.
- 서버 재시작·재접속·청크 왕복 로딩에서도 광석·재고·진행률 일관.
- 원격 산출물이 인벤토리로 자동 지급되지 않음.
- 원격 계산에서는 Three.js 렌더 객체나 개별 아이템 물리 객체를 생성하지 않음.
- 5초 정산과 더 짧은 시간 간격 정산의 결과를 비교해 허용 오차 이내로 일치.

## 8. 관련 월드 컨셉 메모

후속 설계 변경에 따라 TERRA 메인 월드는 **스카이랜드가 아닌 청크 기반 오픈필드 행성**을 목표로 한다. 기존 포탈의 세계관상 외형은 **우주선**, 기존 상점 허브의 세계관상 공간은 **우주정거장**이다. 우주선은 자연 석탄 광석 채굴로 얻은 석탄을 연료로 사용하며, 자연 광석 블록이 군집을 이룬 **자연 광맥**과 구매·코어 제작으로 얻는 설치형 **석탄/철/구리 생성기**는 별개다. 이 항목은 관련 맥락을 위한 설계 메모이며, 이 문서 변경이 월드/이동/공업 기능을 구현했다는 뜻은 아니다.
